# MuseTerm 标题栏交互验证

- 版本：**1.256.0-rc9 / Build 367**
- 日期：2026-11-03
- 环境：本机 macOS，arm64 Debug 构建；系统双击动作 `Maximize`（缩放）。
- 结果：构建成功；窗口关闭回归 **5/5**；原生窗口交互检查 **8/8**。

## 修复

主窗口使用 SwiftUI 原生 `.titleBar` 样式，仅通过现有 WindowConfigurator 隐藏标题文字。终端内容遵守顶部安全区，系统标题栏与窗格标题、分屏按钮分开。没有增加全局鼠标监听、手写缩放或私有 API。

## 原生交互结果

使用独立 QA 应用，鼠标事件经 CoreGraphics HID 通道投递；每次输入前核对目标前台进程。该驱动已先在标准 AppKit 窗口校准。

| 检查 | 结果 |
| --- | --- |
| 单击标题栏不缩放 | 通过 |
| 双击缩放，再次双击恢复原位置和尺寸 | 通过 |
| 双击窗格标题空白区域不缩放整窗 | 通过 |
| 点击分屏按钮增加窗格，不缩放整窗 | 通过 |
| 折叠侧栏后仍可双击缩放与还原 | 通过 |
| 标题栏拖动改变位置，不改变尺寸 | 通过 |
| 截取并检查初始窗口与分屏后的画面 | 通过 |
| 专用 QA 应用退出 | 通过 |

窗口坐标和尺寸为 `(x, y, width, height)`，单位为逻辑点：

- 初始：`(180, 180, 1050, 662)`。
- 双击缩放：`(0, 30, 1440, 813)`。
- 再次双击：`(180, 180, 1050, 662)`，准确恢复。
- 拖动后：`(240, 180, 1050, 662)`，尺寸不变。

使用同一套校准后的驱动测试仓库保留的 **1.256.0-rc3** Debug 旧构建，标题栏双击仍超时，没有缩放。这是旧构建对照，不冒充已安装 rc8 的直接测试。

## 诊断过程与边界

最初直接向进程投递的鼠标事件在标准 AppKit 窗口也不生效，相关超时不计作复现证据。改用已校准的 HID 事件后，只恢复内容安全区仍未通过；同时恢复原生标题栏样式后，完整检查通过。中间的激活竞争、脚本编码错误已修正后重验。

原生“最小化”“填充”“无操作”没有逐项切换验证，应用将这些动作交由 AppKit。未覆盖其它 macOS 版本、全屏和多显示器。截图已实际打开检查，终端内容可见、标题栏与窗格控件分离。

当前安装的应用没有替换；没有提交、推送或发布。
