# 悬浮粘贴、收回及真实 WillDeep 审批联合验收

版本：1.251.0-rc23 / Build 338。正常产品后台入口仍关闭；本轮未提交、未发版、未替换本机应用。

## 改动与测试

后台粘贴将正文和 bracketed paste 标记作为一个有界请求预检、批准和写入，录制及安全检查只使用原正文。队列拒绝与正文不匹配的校验数据；拒绝粘贴时不会先发送开始标记，不自动重发。新路径保持原有清除输入法组合态的行为，不提交旧组合文本。

悬浮面板为顶部控制条预留空间，按钮保持可见可点击，提供中文辅助功能名称和稳定标识；终端文字不再被控制条覆盖。原 rc21 的粘贴残留、隐藏控件失败记录保留在 sidebar-layout-zh.json，不将原失败改写为通过。

干净 HOME/ZDOTDIR 的交互 zsh 基线片段输入 1/1 通过；原子粘贴、安全拒绝和提示保留定向 3/3，首轮完整 611/611。补齐输入法组合态断言后的最终完整回归也为 611/611、0 失败、0 跳过，见 atomic-paste-final-full-unit.json。GUI 候选在组合态补充之前构建，其 SHA 保存在 GUI 报告；最后的组合态改动有最终真实 zsh/完整单测覆盖，未另行重开 GUI 候选。

- 三个结果行 `__QTERM_MAIN_PASTE_RC23_OK`、`__QTERM_FLOAT_PASTE_RC23_OK`、`__QTERM_REATTACHED_RC23_OK` 均真实出现，仅在目标终端出现。
- 原三个终端 UUID/PID/代次保持，UI 和后台均只有三个终端；目标输入序号为 7，对应三次完整粘贴及三次回车。
- 原合成 Agent 实例和唯一问题事项保持；该阶段只验证协议展示，不冒充真实 WillDeep 任务。
- 控件可见，实际点击“收回主窗口标签”成功，恢复原分屏画面后可继续输入。

证据：[普通终端与清理](floating-paste-gui.json)。截图在 CUA 工具输出中实际观察，未保存 PNG，不提供不存在的截图链接。

## 真实 WillDeep 原生接入

随后在另一个自有分屏运行实际 WillDeep 0.115.0-rc1 二进制、私有 Runtime 和本机 mock 模型。所有启动、任务提交、批准和退出输入均通过原生界面执行。

1. 实际粘贴提交测试请求，原生状态由 idle → working → blocked/approval。
2. 记录 PTY PID 1734、代次、WillDeep 前台 PID 5179、实例/运行/会话/task 和唯一审批；实际分离到悬浮面板后，原审批界面仍显示。
3. 点击收回后再次比较原身份及审批 ID，均保持。应用全程运行，没有用这个结果冒充 App 退出/重开验收。
4. 原生按 Y 仅批准 `printf qterm_native_probe` 一次；实际 TUI 显示完成，UI/后台均仅有该任务的唯一完成事项。
5. 点击该完成事项，UI/后台对这个终端同时清零。另一个终端的原问题事项保留，因此全局数字从 2 降为 1，而不是错误清空全部事项。
6. 原生粘贴 `/exit` 后，Agent 为 exited，原 shell 重新成为前台。测试驱动 passed=true，2 次本机模型请求，fixtureErrors 为空；私有 Runtime 随驱动结束回收。

证据：[实际驱动](native-floating-driver.json)、[身份与事项](native-floating-identity.json)。适配器只将两个测试支持路径改成绝对路径、将等待步骤名称改为悬浮/收回；原协议、模型和身份断言未改。独立探针分别记录 before/floating/reattached/completed/read，驱动 SHA 与二进制 SHA 均保留。
