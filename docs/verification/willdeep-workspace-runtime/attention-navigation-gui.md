# 跨项目待处理定位、弹层收起与原进程恢复

日期：2026-10-25。最终候选 1.251.0-rc28 / Build 343。

使用独立原生 QA，两个项目、三个真实后台 PTY，第二项目含两个分屏。Agent 问题由结构化协议夹具提供，用于验证归属和导航，不冒充本轮真实 WillDeep 任务；真实 WillDeep 证据另见原生连续性报告。

## 发现和修复

rc27 点击待处理事项已经切换到正确项目/布局标签/叶子，原问题标为已查看但继续等待回答。然而弹层仍覆盖界面，键盘焦点已经进入终端。随后 Escape 没有关闭弹层，紧接的粘贴出现 `[200~` 残留及 zsh bad pattern。通过入口关闭弹层、Ctrl-C 回到新提示符后，同一终端可正确粘贴执行。不能将此解释为所有 bracketed paste 的根因，也不删去原失败。

rc28 在 `focusAttention` 成功后收起弹层。真实复验从另一项目打开原事项并点击，观察到弹出列表消失，目标项目的两个分屏显示。不再按 Escape、不额外点击分屏，直接粘贴 `printf` 组装的独立标记并回车，`__PENDING_NAV_FIXED_OK` 仅在原目标叶子出现，另两个终端没有该结果。待处理总数仍为 1，原问题 ID 保持且已读，未误解决问题。

## 连续性与清理

旧 QA 正常退出后核实其 PID 已不存在，三个原 PTY 的 UUID/PID/代次保持。只刷新已退出 QA 的程序目录为 rc28，私有工具目录、配置、服务和原进程保持。重开后原两个项目/分屏、选中叶子和原问题均恢复。旧后台没有为对齐界面版本被重启。

首次刷新因 Sparkle framework 符号链接已存在失败，尚未签名或启动；随后仅重建自有 QA 的 Contents，再重新签名和验证。该事件属于 QA 包装，不是产品运行失败。原始记录保留在 JSON。

最终正常退出 QA，逐个比对原 UUID/PID/代次后仅关闭自有三个 PTY；空后台退出，私有凭据、展示授权和独立偏好已清理。没有操作正常 QTerm 或正常 WillDeep Runtime。
