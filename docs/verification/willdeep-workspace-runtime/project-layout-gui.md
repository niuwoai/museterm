# 项目分组、分屏及原进程恢复实际界面验收

日期：2026-10-24；最终版本 1.251.0-rc17 / Build 332。

本轮使用 CUA 操作原生隔离 App，后台为真实 PTY；从 rc15 经 rc16、rc17 的 QA 副本沿用同一私有工作区和原进程，未替换本机应用。

## 已验证

- 创建左右及上下混合的三个分屏，逐个输入由 printf 组装的不同标记。各屏及后台身份快照中各有自己的完整输出，不能靠命令回显冒充成功。
- 从项目表单创建第二项目并指定私有工作目录，实际终端使用该目录；输入第四个独立标记成功。
- 从第三分屏的菜单移入第二项目，原项目树收拢为两个叶子，第二项目增加独立标签；原三个终端 UUID/PID/代次和输出均保持。
- 原生拖动分隔条将比例从 0.5 调到约 0.393525；实际持久化记录保存该比例。重命名项目，并取消一次运行中分屏关闭，四个原进程保持。
- 正常退出旧 QA，四个原 PTY 存活；新版 QA 接回同一服务/PTY PID/代次和标记，完整已保存项目布局、标签、分屏、焦点及比例相同，UI epoch 改变、服务 epoch 保持。
- 最终 rc17 新进程首次点重命名，表单正确显示“重命名项目”及原项目名称；保存后，没有终端输入或强制刷新，工具状态自动发布新名称“布局复验”。再点新建表单时名称和目录为空，不携带旧项目目标。
- 实际确认关闭第二分屏，目标后台记录及 PID 消失，其他三个原进程保持；再次正常退出重开，三个原终端、各自标记和完整布局相同。
- 最终退出 QA，仅回收本轮三个剩余 PTY 和空后台；没有清理其他 QA 或正式会话。

## 发现及修复

1. rc15 实际界面已显示新名称/比例，state.json 仍为旧布局；持久化恢复记录是新的。工具变化检测没有包含 projectLayoutRevision。rc16 将布局修订纳入签名；新增没有进程输出、焦点变化或事件变化的测试，分别等待重命名和调整比例自动发布。原陈旧快照和正确恢复记录保留在 JSON，未掩盖复现。
2. rc16 重开后第一次点重命名出现空白新建表单。两个独立 State 传递弹窗开关和目标存在时序问题；rc17 改为 sheet(item:)，同一个呈现值携带 create/rename(projectID)。上述最终实际界面复验覆盖第一次重命名及之后新建。
