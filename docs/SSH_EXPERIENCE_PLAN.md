# MuseTerm SSH Experience Plan

> 最后更新：2026-07-02
> 当前阶段：SSH Profile 从“保存连接参数”升级为“远程工作台体验层”。

## 北极星

MuseTerm 的 SSH 管理不应只是替用户记住 `user@host -p 22`，而要把远程连接中最常见的麻烦提前消化掉：空闲断线、跳板链路不透明、端口转发难记、密钥和主机指纹风险难判断、连接失败原因难读。

## P0：连接稳定与速度

- 已落地：协议层保活，默认生成 `ServerAliveInterval 30` 与 `ServerAliveCountMax 6`。
- 已落地：连接复用，默认生成 `ControlMaster auto`、`ControlPersist 10m` 与独立 `ControlPath`，让同一主机的新标签页更快打开。
- 已落地：保守自动重连，断线后保留标签页并在终端展示轻量倒计时；仅对疑似临时断线有限重试，认证失败、Host Key 变化和认证身份过多不会自动重连。
- 已落地：自动重连会区分干净退出、认证或安全停止、远端主动关闭、网络中断和未知失败；远端主动关闭不会被误当作网络抖动重连。
- 已落地：自动重连倒计时、重试耗尽和停止重连提示会带上断线原因，解释为什么继续重试或停止。
- 已落地：手动重新连接按钮，自动重试停止或 SSH 标签退出后可在原标签直接重连并保留滚屏历史。
- 已落地：SSH 主机 hover 摘要会解释当前 Profile 的连接行为，直接展示协议层保活、连接复用、自动重连和端口转发失败处理策略；高级 SSH 选项里有手动覆盖时，会按实际生效配置优先说明由高级选项控制。
- 已落地：SSH 主机菜单可预览 MuseTerm 为当前 Profile 生成并传给 OpenSSH 的生效配置，包含目标 alias、Host 块数量、行数和完整配置文本；预览窗口还可写入当前生成配置并复制 DNS、TCP、`ssh -G` 和 `ssh -vvv` 本机检查命令，并能从剪贴板解析这些检查输出、展示状态、证据和下一步建议；建议卡片会直接展示关联步骤标题、检查命令和证据行，也可复制 Markdown 结果报告。
- 下一步：把断线原因沉淀到结构化命令块或 Runbook，方便复盘远端会话稳定性。

## P0：端口转发工作流

- 已落地：Profile 支持结构化端口转发，覆盖 `LocalForward`、`RemoteForward` 和 `DynamicForward`。
- 已落地：存在结构化端口转发时自动生成 `ExitOnForwardFailure yes`，避免端口冲突或转发失败悄悄被吞。
- 已落地：编辑器会在连接前提示重复的本地或远端监听地址，避免多个转发争抢同一个端口。
- 已落地：SSH 主机列表会显示端口转发数量徽标，hover 摘要列出 Local/Remote/Dynamic 的监听与目标端点；主机菜单可复制端口转发摘要。
- 已落地：端口转发摘要会为 LocalForward 附上本地 HTTP/HTTPS 入口，为 DynamicForward 附上 SOCKS 代理 URL，复制摘要和侧栏 tooltip 都会展示这些入口；如果多条转发解析到同一个本地入口，入口区会稳定去重，但规则摘要仍保留每条转发。
- 下一步：把文本格式升级为表格化编辑器，按“本地端口、远端目标、SOCKS 代理”分类展示。
- 下一步：连接成功后把这些文本入口升级为可点击入口，例如 `localhost:8080` 或 SOCKS 代理地址。

## P1：跳板机可视化

- 当前能力：Profile 已支持多跳 `ProxyJump`，并支持每一跳单独配置用户、端口和密钥。
- 已落地：侧栏 tooltip 和编辑器会展示“本机 -> 跳板 1 -> 跳板 2 -> 目标机”的链路摘要。
- 已落地：连接失败或主机解析失败时，诊断会结合 Profile 路径指出失败更像发生在目标机、第几跳跳板机或未知位置，并展示完整路径与证据行。
- 已落地：连接失败时会给出可粘贴的只读探测命令，覆盖第一跳端口检查、生成配置展开检查和详细 OpenSSH 链路检查。
- 已落地：链路探测命令背后已有结构化诊断计划模型，记录 DNS、TCP、config 和逐跳 verbose 检查的步骤类型、目标主机、端口与 OpenSSH alias。
- 已落地：生效配置预览窗口可展示当前生成的 OpenSSH config，并在写入该配置后复制本机 DNS、TCP、`ssh -G` 和 `ssh -vvv` 检查命令，避免排障命令引用过期配置。
- 已落地：SSH 主机菜单可打开诊断计划窗口，直接预览这些结构化检查步骤；支持复制全部命令或逐条填入本地终端，填入时不自动回车执行。
- 已落地：诊断计划步骤可以解析执行结果，把 DNS、TCP、生成配置和 verbose OpenSSH 输出归类为通过、失败、需关注或未知，并保留关键证据行；生效配置预览窗口会据此给出下一步建议，并在建议卡片里显示关联步骤标题、检查命令和证据行。
- 已落地：生效配置预览的建议卡片可直接复制推荐检查命令，或从剪贴板解析这条推荐检查的输出，减少回到完整命令列表定位步骤的来回。
- 已落地：当已解析检查没有失败但仍有剩余步骤时，诊断建议会锚定第一条未完成检查，并在生效配置预览卡片和 Markdown 报告建议区带出对应步骤和命令。
- 已落地：诊断计划窗口可从剪贴板解析单步诊断输出，在对应步骤下展示状态、摘要和证据行，并汇总、复制或清空已解析结果；复制结果会生成可沉淀到 Runbook 且写入当前诊断建议的 Markdown 报告，关联步骤会同时写入步骤编号、步骤标题、关联检查命令和关联证据，并默认复用 Runbook 脱敏规则处理常见密钥、token、密码、Authorization Bearer、私钥块和 URL 凭据，同时在报告头部标明是否检测到疑似敏感内容以及是否已脱敏。
- 下一步：把诊断结果持久记录到面板与 Runbook，进一步区分 DNS、端口、认证还是 ProxyJump 失败。

## P1：安全护栏

- 当前能力：Profile 已区分开发、预发、生产环境，并可为生产环境强制高危操作确认。
- 已落地：`ForwardAgent yes`、关闭 Host Key 校验、known_hosts 写入 `/dev/null` 等高风险高级选项会在编辑器中显示明显提示。
- 已落地：SSH 主机列表会用健康徽标前置展示连接前预检问题和高风险 SSH 选项，hover 摘要列出配置问题或安全提醒。
- 已落地：编辑器会在连接前提示目标主机和跳转机的密钥文件路径不可用，减少保存后才发现认证失败的情况。
- 已落地：编辑器会在目标机或跳转机私钥文件权限对 group/others 过宽时提示 `chmod 600` 修复命令，避免 OpenSSH 忽略私钥后才失败。
- 已落地：Host Key 校验失败时，终端诊断会要求先核对服务器新指纹；确认可信后再展示 `ssh-keygen -R` 清理旧 known_hosts 记录的命令，并尽量带上 OpenSSH 报出的 known_hosts 文件位置。
- 下一步：Host Key 首次连接时展示更细的指纹比对说明。

## P2：配置导入与双向同步

- 已落地：从 `~/.ssh/config` 导入明确 Host，保留原始别名、用户、端口、密钥、跳板、常见转发规则、保活和连接复用设置，并跳过通配符 Host。
- 已落地：MuseTerm 编辑后的 Profile 可复制为 OpenSSH config 片段，默认只进入剪贴板，不覆盖用户原文件。
- 已落地：Profile 编辑器可维护分组与标签，例如个人服务器、公司内网、云主机、临时机器；侧栏支持按名称、主机、用户、环境、分组、标签与跳转机信息搜索 Profile，并可按标签筛选、按分组展示。
- 下一步：增加批量标签管理和大量主机下的分组折叠。

## P2：智能诊断

- 已落地：终端输出旁路识别常见 SSH 失败，并追加 MuseTerm 提示，覆盖认证失败、Host Key 校验失败、连接超时、连接被拒绝、认证身份过多和端口转发失败。
- 已落地：`Host key verification failed` 会给出 known_hosts 定位与保守清理命令，且不会自动执行。
- 已落地：多跳 SSH 失败会追加链路定位摘要，尽量把 OpenSSH 输出里的 host/port 映射回目标主机或具体跳板机。
- 已落地：失败提示会追加下一步探测命令；Host Key 风险场景下只展示配置和端口检查，不建议立即 `ssh -vvv` 重连。
- 下一步：解析 SSH stderr 常见错误并给出面向行动的建议：
- `Permission denied`：检查用户名、密钥、`IdentitiesOnly` 或 agent。
- `Connection timed out`：建议检查端口、防火墙、VPN、跳板链路。
- `Too many authentication failures`：建议启用 `IdentitiesOnly yes` 或指定更少密钥。

## 验收原则

- 每项能力必须能在生成的 OpenSSH config 中被测试验证。
- 默认行为应提升稳定性和速度，但不能覆盖用户在高级选项中手写的同名 OpenSSH 配置。
- 新增可见文案必须走本地化资源。
- 任何可能改变安全边界的选项都需要明确提示，而不是藏在高级参数里。
