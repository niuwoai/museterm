# 图片列协议

版本：1.258.0-rc1 / Build 373。

一个标签默认是完整的字符终端。标签里的程序可以用私有序列 OSC 7771 报出自己的图片，终端就在右侧展开一列约 120pt 的缩略图。点缩略图看大图，草稿图片带删除图标。列表为空或程序退出时列收起，终端恢复满宽。

这不是单元格图形。Kitty、iTerm2 和 Sixel 仍由终端自己的图形策略绘制，与这一列互不影响。

## 帧

```text
ESC ] 7771 ; v=1 ; <op> ; <字段，以 ; 分隔> BEL
```

终止符是 BEL（0x07），不是 ST（`ESC \`）。base64 里会出现字节 0x5c，用 ST 会把帧从中间截断。SwiftTerm 会吞掉它不认识的 OSC，所以帧不会显到屏幕上。777 和 1337 已被占用，7771 空着。

字段里的标识（id、nonce）长 1–64，只含 `[A-Za-z0-9-]`。名称长度不超过 255，不含控制字符。

## 程序写给终端

| op | 字段 | 作用 |
| --- | --- | --- |
| `hello` | `<名称与版本>` | 声明已接入。终端只有见到过 `hello` 才会把图片字节写进去。 |
| `bye` | 空 | 程序退出，列收起。 |
| `list` | JSON 数组 | 当前图片，每项 `{"id","name","mutable"}`，不带像素。空数组收起列。最多 12 张。 |
| `ack` | `<nonce>;<id>` | 粘贴已成为草稿附件，缩略图改挂到这个 id。 |
| `reject` | `<nonce>;<原因>` | 粘贴被拒绝。缩略图保留并标为未接收，可直接删掉。 |
| `remove` | `<id>` | 确认这张图已删除。 |
| `blob` | `<id>;<序号>;<总片数>;<base64>` | 程序自己产生的图片像素，序号从 0 开始。 |

## 终端写给程序

终端把这两种帧当普通输入写入，不走仿真器回复通道。程序必须在自己的按键解析之前把它们从输入里拿掉；willdeep 用一根管道接在标准输入前面做这件事。

| op | 字段 | 作用 |
| --- | --- | --- |
| `drop` | `<nonce>;<序号>;<总片数>;<base64>` | 用户粘贴的 PNG。 |
| `delete` | `<id>` | 用户点了删除图标。 |

## 限制

- 只收 PNG。解码后不超过 8 MB。
- 一个标签最多 12 张。
- 单帧不超过 60,000 字节，超过的像素拆成多帧。运行时输入单次写入上限 65,536、排队总量 131,072，所以两帧总能一起排进去。
- 输入记录里只留短文本（如 `ESC ]7771;drop;<nonce>`），不记图片字节。
- 一帧超过 5 秒还没有终止符就丢弃，不会一直卡住后面的输入。
